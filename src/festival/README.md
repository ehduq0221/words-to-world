# 축제 스튜디오

기존 게임과 별도로 확인하는 하루 축제 기획·미리보기입니다. 게임 예산·만족도·게임 저장을 읽거나 변경하지 않습니다.

## 실행

프로젝트 루트에서:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

http://127.0.0.1:8000/src/festival/dev.html

1. 제공 차트를 참고한 실제 가수 후보를 최대 3팀 선택합니다.
2. 포스터의 위·아래 버튼으로 순서를 바꿉니다.
3. 대운동장·초록 B 장소·예산·부스·응원봉·색종이 피날레·폭죽 시점을 정하고 기획안을 저장합니다.
4. 미리보기를 누르면 선택한 실제 캠퍼스 건물 앞의 게임용 무대에서 공연이 진행됩니다.
5. 공연 버튼으로 개별 무대를 볼 수 있습니다. 일시정지·다시 보기·닫기 또는 Escape를 사용할 수 있습니다.
6. 소리는 기본으로 꺼져 있습니다. `소리 켜기`를 눌러 Web Audio 합성음을 재생합니다.

미리보기는 준비 4초, 공연당 16초, 공연 사이 3초, 마무리 8초로 하루를 압축합니다. 포스터의 17·19·21시는 게임용 타임테이블이며 실제 축제 공지가 아닙니다. 원래 캠퍼스 지도 형상을 재사용하지만 무대·관객·부스 배치는 가상 연출입니다.

## 파일과 경계

- `index.js`: `initFestival()` 진입 함수와 기획 UI. `#festival` 안에 렌더링합니다.
- `plans.js`: 기획안 생성·검증·비용·브라우저 저장. 선호도 제출과 구분합니다.
- `player.js`: 모달 미리보기·공연 순서·재생 상태. 입력 기획안을 읽기만 합니다.
- `scene.js`: 기존 Three.js·`loadCampus`·`createCampus`·`createCamera` 재사용. 새 엔진 없음.
- `audio.js`: 오리지널 합성 패턴. 외부 음원·영상·API 호출 없음.
- `dev.html`, `dev.js`: 계획서 기준 독립 개발 진입점. `preview.html`은 기존 주소 호환용 이동 페이지.
- `gameApi.js`: 후속 게임 연결의 공개 API 진입점. 현재는 임시 어댑터를 re-export합니다.
- `stubGame.js`: 1차 임시 어댑터. 현재 독립 기능에서는 호출하지 않으며 실제 게임 연결 시 삭제합니다.
- `public/data/festival.json`: 차트 참고 실제 후보·게임 비용·기준 건물 ID·축제 위치 오프셋·축제 구성.

저장 키는 `words-to-world:festival-plans:v1`이고 최대 50개입니다. 새로고침 후 저장 목록에서 불러옵니다. 브라우저·주소·포트가 바뀌면 저장소가 다릅니다. 게임 저장 키 `words-to-world:save`와 분리됩니다. 저장 실패나 손상 데이터가 있으면 메시지를 표시하며 자동 덮어쓰지 않습니다.

## 게임 완성 후 연결 — 아직 미구현

`IMPLEMENTATION_PLAN.md`의 2차 연결 순서를 따릅니다.

1. 기존 화면에 축제 전용 `#festival` 영역·CSS와 진입 버튼을 추가합니다. 다른 담당 패널은 수정하지 않습니다.
2. `src/main.js`에서 `initFestival`을 가져와 지도 초기화 이후 호출하고, 전체 기능 등록 이후 `startGame()`을 호출합니다.
3. 게임 날짜·학기·운영 지표는 쿼리 없는 `../game/index.js` 공개 API로만 연결합니다. `registerArea('festival', ...)`에 학기별 개최 결과를 저장합니다.
4. 실제 개최 버튼은 미리보기 버튼과 구분합니다. 선택 라인업과 게임 학기를 검증한 뒤 `applyEffect`로만 비용·만족도를 반영합니다. 예를 들어 `festival:held:2026-1`로 같은 학기의 중복 개최를 방지합니다.
5. 실제 축제 일정과 하루 개최일은 확인한 자료·사용자 선택으로 결정합니다. 현재는 기획·미리보기만 언제든 가능하며 실제 일정을 주장하지 않습니다.
6. 실제 개최 후 학생 반응을 `addReaction`으로 추가하고, 대사는 지정된 `public/data/dialogues/festival.json`에 둡니다. 예상 반응과 실제 반응을 구분합니다.
7. 3차에 `onSettlementEnd`의 예산 음수 게임 종료와 새 게임 안내를 연결합니다.

현재 `initFestival()`은 데이터 fetch를 위해 비동기 함수입니다. 현재는 게임 영역을 등록하지 않습니다. 나중에 게임 상태를 등록하는 코드를 추가할 때는 `startGame()` 이전에 등록이 끝나도록 호출을 기다려야 합니다.

## 차트 후보와 초록 위치

후보는 사용자 제공 멜론 차트에서 발췌했으며, 출처 수신일은 2026-11-06입니다. 원본 텍스트의 차트 기준 시각은 확인되지 않았으므로 실시간 갱신·현재 순위로 표시하지 않습니다. 후보 카드의 숫자는 제공 자료의 곡 순위입니다. 가수의 실제 음악 장르를 단정하지 않고, 필터는 게임의 노을·아이돌·그루브 공연 연출 분류로 사용합니다.

기본 장소는 대운동장이며 초록 B는 19호관 왼쪽의 이미지 기준 대안 위치입니다. `anchorBuildingId`로 기준 건물을 찾고, 지도 기준 `rightOffset`·`downOffset`과 `scale`로 배치를 조정합니다. 장소 ID는 축제 내부 ID이며, 추후 건물 선택 이벤트와 연결할 때 기준 건물 ID를 사용합니다. 작은 위치 안내도는 원본 좌표 투영이므로 지도 통로 보정이 적용된 실제 3D와 약간 다를 수 있습니다. 미리보기의 `지도에서 위치 보기`로 3D 내 위치도 확인할 수 있습니다.

이전 저장의 가상 가수와 기존 장소는 `archived`로 보존합니다. 새 후보·장소 목록에는 나오지 않으며, 이전 기획안을 불러오면 그대로 복원됩니다. 라인업의 ×로 이전 후보를 제외하고 실제 가수로 교체할 수 있습니다.

폭죽은 색종이 피날레와 별개입니다. 시작·공연 사이·종료 중 선택한 시점만 실행하고, 일시정지·다시 보기에도 대응합니다. 소리를 켜면 직접 합성한 폭죽 효과음이 함께 재생됩니다.

기본 공연 화면은 주변 건물과 하늘을 함께 보는 넓은 구도입니다. `무대 가까이 보기`로 접근하고 `주변 함께 보기`로 돌아옵니다. 기본 화면에서는 무대를 직접 가리는 건물만, 가까운 화면에서는 무대 주변 건물을 반투명 처리하며, 전체 지도 보기에서도 원래 건물 모습을 확인할 수 있습니다. 폭죽은 무대 배율과 별개인 캠퍼스 규모로 일곱 발이 연속으로 터집니다.

## 축제 속으로 들어가기

- `빠르게 보기`: 현재 라인업을 2배속 재생합니다. 비어 있으면 예시 라인업을 사용하며 편집 중 기획안은 변경하지 않습니다.
- 저장 목록의 `불러오고 미리보기`: 저장 내용을 복원한 뒤 바로 체험 화면으로 들어갑니다. 편집 중 내용이 있으면 화면 안에서 먼저 확인합니다.
- `밖에서 보기` / `관객 속으로 입장` / `캠퍼스 전체`: 시점을 바꿉니다. 관객 속에서는 앞뒤·좌우 이동 버튼과 방향키를 사용하고, 환호 버튼으로 함께 반응할 수 있습니다.
- 가수별 무대는 `profiles.js`에서 정의합니다. IVE의 금빛·보랏빛 왕관 무대와 리센느의 민트·분홍 꽃 형태 무대 등, 배경·장식·대형·움직임·창작 합성 패턴을 구분합니다. 실제 공연을 복제하지 않습니다.
- `폭죽만 미리보기`: 선택 가수가 없어도 폭죽을 단독으로 시험합니다. 시간 제한 없이 닫을 때까지 설정을 바꿔 확인할 수 있습니다.
- 폭죽 위치는 기획 화면에서 저장합니다. 체험 화면의 위치 변경은 해당 미리보기에만 적용합니다. `지금 폭죽 미리보기`는 설정한 순서와 무관하게 즉시 발사합니다.
- 폭죽이 터지면 하늘 시점으로 잠시 이동합니다. 관객이나 무대에 가려지지 않도록 한 뒤 원래 시점으로 돌아옵니다. 동작 줄이기 설정은 입자 움직임을 줄입니다.
- 실제 음원·안무·목소리는 사용하지 않으며 음악과 효과음은 직접 합성합니다.
- 화면 초기 로딩 중에는 제어 버튼을 비활성화하고, 실패하면 구체적인 오류를 화면에 표시합니다. 기존 게임 연결은 하지 않았습니다.

## 참여 기능과 공연장 구성

- `응원봉 흔들기` / L: 손에 든 응원봉을 흔듭니다. 네 가지 색 중 선택할 수 있습니다.
- `박자에 맞춰 응원봉 흔들기` / F: 표시가 넓은 중앙 구간에 올 때 천천히 흔듭니다. 약 1.3~2.1초 주기로 참여하고 연속 참여를 표시합니다.
- `공연 사진 저장` / P: 현재 3D 장면을 PNG로 내려받습니다. 아티스트 이름과 캠퍼스 지도 출처가 포함됩니다.
- 무대와 관객 사이에 금속 펜스와 안내 통로, 형광 조끼·반사띠·STAFF 표시의 안내요원 4명을 배치했습니다. 관객석 이동은 펜스 뒤로 제한합니다.
- 아티스트 성별에 맞춰 게임용 헤어·의상을 표현합니다. 길고 짧은 머리와 바지·스커트를 섞어 사용하며, 실제 외모나 의상을 복제하지 않습니다. 확인한 구성 인원은 aespa 4명과 IVE 6명이며 출처는 [aespa 공식](https://aespa-official.jp/)과 [IVE 공식](https://ive-official.jp/)입니다. 그 외 무대 캐릭터 수는 게임용 연출입니다.

공연 시간에 따라 17:00 노을·19:00 보랏빛 저녁·21:00 달과 별이 보이는 밤으로 배경이 전환됩니다. 가수별 무대 디자인은 유지하면서 주변 밝기를 조정합니다. 실제 날짜의 일몰 계산이 아닌 게임용 시간 연출입니다. 폭죽 단독 미리보기는 21시 밤 배경에서 시험합니다.

기본 장소는 대운동장입니다. 기존 초록 A를 선택했던 저장 기획안도 대운동장으로 열립니다. 저장 호환을 위해 내부 장소 ID는 유지하되 `anchorBuildingId`는 `outdoor:main-field`로 변경했습니다. 초록 B는 대안 장소로 유지합니다.

## 선택한 학생의 인천대학교 축제

대운동장 무대에 학교 이름·트러스·보라색 LED 타워·금색 천막을 배치했습니다. 밤의 도시 실루엣은 사진에서 영감을 받은 게임용 배경입니다.

학생은 기존 캐릭터 화면에서 선택합니다. 축제는 `words-to-world-character` 저장값을 읽기만 하고, 이름·학과와 선택된 외형의 머리·피부·재킷 색을 축제용 초상·3D 캐릭터에 반영합니다. `내 학생으로 입장`하면 자신의 캐릭터를 뒤따라가며 관객석을 이동합니다. 학생 미선택은 명확히 표시하고 선택 화면으로 연결합니다. 같은 브라우저의 같은 주소에서 선택해야 하며, localhost와 127.0.0.1 사이에는 저장이 공유되지 않습니다.

캐릭터 기능을 import하거나 수정하지 않습니다. 외형 색상은 현재 캐릭터 선택 팔레트에 맞춘 축제 어댑터이므로 그 팔레트가 변경되면 student.js도 갱신해야 합니다.

`박자에 맞춰 응원봉 흔들기` / F는 세 박자에 한 번, 약 1.3~2.1초 주기로 천천히 참여합니다. 가운데가 반짝일 때 누르면 자신의 응원봉과 학생 캐릭터가 흔들리고 연속 참여를 표시합니다. 빠른 비트 게임과 별도의 점수 경쟁은 사용하지 않습니다. 자유롭게 계속 흔들기는 접힌 부가 도구에서 L로 사용할 수 있습니다.

### 선택 학생의 직접 참여

‘점프하며 환호’ 또는 Space로 내 학생이 직접 점프합니다. 버튼에 초점이 있어도 Space를 사용할 수 있으며 관객 시점이 유지됩니다. 일시정지 중에는 재생을 이어갑니다. 축제용 캐릭터는 선택 팔레트에 맞춘 얼굴·헤어·재킷·운동화와 관절을 사용하며 실존 출연진의 외모를 재현한 모델은 아닙니다.

### 기획 화면 이동

가수 후보와 현재 라인업·예상 지출을 함께 봅니다. 후보는 좌우 화살표로 PC 4팀·작은 화면 2팀씩 넘기며 선택은 유지됩니다. ‘장소·축제 구성’, ‘불러오기·저장한 조합’ 탭에서도 현재 조합을 확인할 수 있습니다. 예시 조합은 후보 위에서 펼치고, 저장·불러오기·빠른 보기·축제 체험은 상단에서 바로 실행합니다. 모바일은 현재 조합을 아래에 표시하며, 내용이 많은 보조 화면은 해당 영역 안에서 스크롤할 수 있습니다.

확인: PC·모바일에서 후보 이동과 선택 유지, 라인업 동시 표시, 설정·폭죽 편집, 저장·불러오기·새로고침 복원, 예시 조합, 문서 전체 가로·세로 넘침 없음과 브라우저 오류 없음을 검증했습니다.
